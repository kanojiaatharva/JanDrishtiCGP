# JanDrishti — AI Pipeline Specification

## 1. AI Philosophy

JanDrishti uses AI to understand and organize citizen demand, not to replace government judgment.

The AI pipeline must be:

- structured;
- schema-validated;
- observable;
- versioned;
- confidence-aware;
- multilingual;
- privacy-conscious;
- reversible.

---

## 2. Pipeline

```text
Citizen Input
      ↓
Consent Check
      ↓
Audio → Speech-to-Text
      ↓
Language Detection
      ↓
Normalization
      ↓
Gemini Structured Extraction
      ↓
Schema Validation
      ↓
Confidence Evaluation
      ↓
Citizen Confirmation
      ↓
Embedding
      ↓
Semantic + Geographic Clustering
      ↓
Evidence Enrichment
      ↓
Priority Engine
      ↓
Explainable Recommendation
      ↓
Human Review
```

---

## 3. Speech-to-Text

Use Google Cloud Speech-to-Text.

Input:

- mobile audio;
- WhatsApp voice media;
- future IVR audio.

Output:

```json
{
  "transcript": "...",
  "language": "hi",
  "confidence": 0.94
}
```

Rules:

- retain provider/model metadata;
- retry transient failures;
- never treat low-confidence transcription as certain;
- allow citizen correction.

---

## 4. Gemini Structured Extraction

Gemini should return JSON matching a strict schema.

Example:

```json
{
  "category": "WATER",
  "subcategory": "DRINKING_WATER",
  "summary": "Unsafe drinking water and frequently broken handpumps",
  "severity": 4,
  "urgency": 4,
  "entities": ["drinking water", "handpump"],
  "location": {
    "administrative_area": "Ward 14",
    "source": "USER_CONFIRMED"
  },
  "confidence": 0.94
}
```

Allowed category values are controlled by backend configuration.

---

## 5. Location Rules

AI may extract a location mention, but it must not invent exact coordinates.

Location priority:

1. user-confirmed GPS;
2. WhatsApp shared location;
3. user-selected map point;
4. verified address;
5. administrative location explicitly stated;
6. AI-extracted place mention.

If multiple locations are mentioned, mark the report as requiring clarification.

---

## 6. Prompt Versioning

Every AI call must record:

- provider;
- model;
- model version;
- system prompt version;
- extraction schema version;
- timestamp;
- latency;
- token/cost metadata if available.

Prompts must live in version-controlled files.

Example:

```text
prompts/
  issue-extraction-v1.md
  recommendation-explanation-v1.md
  translation-v1.md
```

---

## 7. Privacy Boundary

Before AI processing:

```text
Citizen Record
  ↓
PII minimization
  ↓
AI-safe payload
```

Do not send:

- phone number;
- authentication tokens;
- unnecessary name;
- unnecessary address;
- government identifiers;
- unrelated profile data.

AI should receive the minimum content needed to understand the issue.

---

## 8. Embeddings

Generate an embedding for a normalized issue representation, for example:

```text
category + subcategory + normalized issue summary + locality
```

Do not embed raw PII.

Embeddings are used to identify semantically similar requests.

---

## 9. Clustering

Cluster using multiple signals:

```text
Semantic similarity
+
Geographic proximity
+
Administrative area
+
Time window
+
Issue category
```

Example:

```text
"Road has many potholes"
"Road badly damaged"
"सड़क में बहुत गड्ढे हैं"
"Road needs repair"
```

can form a common road-condition cluster.

The cluster title can be generated by AI but should be derived from validated member data.

---

## 10. Hotspot Detection

A hotspot is not simply "the area with the most complaints."

Suggested inputs:

- report volume;
- unique citizen count;
- recurrence;
- recent growth;
- geographic density;
- severity;
- population;
- infrastructure gap.

Hotspot scores must be reproducible.

---

## 11. Priority Engine

The default score is:

```text
Demand             30%
Severity           20%
Need Gap           20%
Infrastructure     15%
Population         10%
Plan Gap            5%
```

All components are 0–100.

```text
score =
  0.30 * demand +
  0.20 * severity +
  0.20 * needGap +
  0.15 * infrastructureGap +
  0.10 * populationNeed +
  0.05 * planGap
```

The exact formula must be configurable and versioned.

---

## 12. Recommendation Generation

The AI can explain a deterministic score.

It must not fabricate evidence.

Recommendation input should contain:

```json
{
  "area": "Ward 14",
  "category": "WATER",
  "priority_score": 92,
  "evidence": {
    "reports": 1284,
    "growth_rate": 38,
    "water_coverage": 42,
    "population": 18430,
    "active_projects": 0
  }
}
```

Output:

- recommended intervention;
- reasons;
- evidence references;
- uncertainty;
- suggested next verification step.

---

## 13. Hallucination Controls

The recommendation model must:

- only use supplied evidence;
- identify missing evidence;
- never invent project budgets;
- never invent infrastructure coverage;
- never claim an officer approved something;
- never claim an intervention has happened unless backend state confirms it.

---

## 14. Confidence

Store confidence separately for:

- transcription;
- extraction;
- location;
- cluster membership;
- recommendation evidence completeness.

Confidence must never be interpreted as a probability of government impact.

---

## 15. Human Review Thresholds

Example:

```text
High confidence + complete evidence
→ normal officer review

Medium confidence
→ recommendation shown with warning

Low confidence
→ request clarification/evidence
```

Thresholds are configurable.

---

## 16. Evaluation

Create an evaluation dataset containing manually labeled:

- category;
- subcategory;
- language;
- severity;
- location;
- cluster membership.

Track:

- extraction accuracy;
- language-specific accuracy;
- false location rate;
- cluster quality;
- recommendation evidence completeness;
- correction rate.

No model should be promoted solely on a single aggregate score.

---

## 17. AI Failure Modes

### Incorrect transcription

Mitigation:
- transcript confidence;
- citizen correction.

### Wrong category

Mitigation:
- constrained categories;
- confidence threshold;
- human review.

### Wrong location

Mitigation:
- explicit location source;
- confirmation;
- no AI-generated coordinates.

### Duplicate cluster

Mitigation:
- semantic + geographic thresholds;
- officer/analyst merge/split tools.

### Hallucinated evidence

Mitigation:
- recommendation model only receives structured evidence;
- evidence IDs stored;
- no unsupported claims allowed.

---

## 18. Model Abstraction

Implement an internal interface:

```typescript
interface AIProvider {
  transcribe(input: AudioInput): Promise<TranscriptResult>;
  analyzeIssue(input: IssueInput): Promise<StructuredIssue>;
  generateEmbedding(input: string): Promise<number[]>;
  explainRecommendation(input: RecommendationContext): Promise<Explanation>;
}
```

This prevents vendor lock-in.
